01 / DATA FLOW

From file to answer.

  1. 01 · WEB CLIENTReact

    Accepts PDF, DOCX, or TXT files up to 10 MB and sends them to FastAPI.

  2. 02 · EXTRACTIONFastAPI + parsers

    Validates type and size, extracts text, and preserves page numbers. The temporary file is removed after processing.

  3. 03 · PASSAGESChunking + SQLite

    Normalizes text, creates 1,100-character chunks with 160-character overlap, and stores text with source metadata.

  4. 04 · RETRIEVALLexical search

    Compares question and passage terms, ranks matches with cosine similarity, and selects up to three sources.

  5. 05 · GENERATIONOpenRouter · free route

    The server sends the question and retrieved excerpts to the model. The API key stays in Render environment variables and never reaches the browser.

  6. 06 · RESULTAnswer + sources

    The UI displays the answer, cited passages, and recent questions; chat history is stored in SQLite.

Data boundary: the original uploaded file is not sent to OpenRouter. The provider receives the question and relevant extracted passages — up to about 6,000 context characters per request.
02 / DESIGN DECISIONS

What happens inside.

RETRIEVAL

Retrieve first, generate second

Lexical retrieval narrows the context to relevant excerpts. The LLM receives only the question and those excerpts; its system prompt says to treat document content as untrusted and not follow instructions inside it.

SOURCES

Answers you can verify

Each API source includes a filename, page, excerpt, and relevance score. The model is asked to cite sources so readers can check claims against the document.

SECRETS

The key stays server-side

React calls the app's own API. FastAPI reads OPENROUTER_API_KEY from the environment, never from the browser or public repository.

PROCESSING

Synchronous path for a small demo

Indexing runs during the upload request. This keeps the demo simple; large files and higher traffic need a task queue and resource limits.

04 / KNOWN GAPS

Before using real customer data.

User isolation: accounts and access checks for every document and conversation.

Indexing queue: background jobs, retries, and processing status.

Durable storage: PostgreSQL, object storage, backups, retention rules, and data deletion.

Security and quality: request limits, content-based file validation, retrieval evaluation, document-injection tests, and citation accuracy checks.
